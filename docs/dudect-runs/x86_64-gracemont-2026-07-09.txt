  Notes:
    Clean run: the planted sentinel_leak fails (56519) and all 20 real
    targets pass with wide margin (max real |t| = 1.87, validate_key).
    No borderline readings on this host; every |t| trace walked around
    zero rather than scaling with sqrt(n).

    keygen: reads 0.06 here.  Its Fisher-Yates index sampler draws a
    fixed number of PRG bytes and reduces them into range with a
    multiply-shift (no reject loop, no hardware divide), so total PRG
    consumption and total time are independent of the secret seed.  The
    divide-free reduction matters on Gracemont / Atom, where divide
    latency is operand-dependent and a modulo reduction could otherwise
    leak the dividend.

    perm_gf16_route and the keygen shuffle are access-ORDER paths: a
    total-time PASS here is corroborating evidence.  Their obliviousness
    (masked scans / masked swaps, no secret-indexed access) rests on
    construction and code inspection; total-time dudect is largely blind
    to access-order effects.

  flow across seeds.  This gates the RSv6 key-schedule paths in
  proof/rs_epoch_gf8.c on the Gracemont / Atom uarch:
    - derive_node selects a child with memcpy(cur, bit ? r : l, sb):

    - compute_cover loops a t-dependent (public) number of times and
      expands each node with a fixed-length PRG draw independent of
      the seed contents.
    - advance recomputes the cover with fixed passes and zeroizes the
      retired cover seeds; no seed-dependent branch or index.

v1.10.0 RSv6 forward-secure key-schedule gate status -- 2026-07-13
                                                     (Gracemont)
================================================================

  All three RSv6 out-of-circuit key-schedule secret-input targets
  PASS at the release-gate sample count (200000/class, nmin=196000
  after crop): keygen 0.04, derive_sk 0.04, state_advance 0.10.

  This confirms the GGM epoch key schedule is timing-independent of
  the secret master seed / cover seeds on a second x86_64
  microarchitecture (Gracemont), complementing the Sandy Bridge-EP
  evidence (x86_64-2026-05-26.txt Run 7) and the Apple M1 evidence
  (aarch64-darwin-m1-2026-05-26.txt Run 6).  The constant-time scope
  is seed-independence, not epoch-position independence, which is by
  design: the schedule is public in t, and hiding the signer's
  epoch / ring position is the in-circuit secret-dir membership walk
  plus the slot-free uniform gate stream of the public-dir epoch walk.
  The in-circuit V6 additions (SCALE_INSTANCE-based epoch directions)
  add no secret-input primitives beyond the existing GF(2^8) gate set
  already gated in Run 1.

Migration note -- 2026-07-18 (v1.10.1, libtalos_ichor)
================================================================

  As of v1.10.1 the AES-CT64 (aes_ct64_*) and primitive Grostl
  (grostl256_msg / grostl512_msg) timing targets moved to
  libtalos_ichor together with the primitives themselves; their
  constant-time evidence now lives in ichor's own dudect trail.  The
  Run blocks above remain the accurate record of what voleith's
  harness produced on their stated dates; future voleith runs no
  longer emit those rows.  The Grostl in-circuit witness-builder
  target (voleith_grostl256_gf8_build_witness_msg) and all field /
  erasure / RS targets stay voleith-side and continue here.
